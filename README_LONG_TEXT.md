# CapsWriter 长文本处理与归纳工具

## 功能概述

本工具是CapsWriter离线工具套件的重要组成部分，专门用于处理长文本、音频或视频字幕内容。通过AI大模型进行分段处理，生成结构化、格式化的归纳文档，自动解决AI大模型上下文长度限制的问题。

## 主要特性

### 🚀 核心功能
- **智能分段处理**：自动将长文本分割为符合AI模型上下文限制的段落
- **多种处理类型**：支持总结、润色、纠错、关键词提取、结构化整理
- **上下文保持**：在分段处理时保持段落间的语义连贯性
- **多模型支持**：集成DeepSeek、豆包(Doubao)、Claude、LM Studio等AI模型

### 📁 文件支持
- **文本文件**：TXT、MD、DOCX、DOC、RTF
- **字幕文件**：SRT、VTT
- **输入方式**：直接输入、文件拖拽、文件选择

### 💾 输出功能
- **格式化文档**：支持导出为Markdown、Word、PDF等格式
- **结果管理**：复制、保存、导出处理结果
- **历史记录**：完整的处理历史管理和版本控制

## 快速开始

### 安装依赖

确保已安装必要的Python依赖：

```bash
pip install PySide6 asyncio pathlib
```

如需处理Word文档，还需安装：

```bash
pip install python-docx
```

### 启动应用

```bash
# 方法1：直接运行启动脚本
python run_long_text_app.py

# 方法2：直接运行主程序
python long_text_gui.py
```

## 使用指南

### 1. 文本输入

#### 直接输入
- 在左侧文本输入框中直接输入或粘贴要处理的文本

#### 文件拖拽
- 将支持的文本文件直接拖拽到文本输入框中
- 系统会自动读取文件内容并显示

#### 文件选择
- 点击"加载文件"按钮选择本地文件
- 支持多种文本格式的自动识别和读取

### 2. 处理设置

#### 处理类型选择
- **总结**：提取文本关键信息，生成简洁摘要
- **润色**：优化文本语言表达，提升可读性和专业性
- **纠错**：检测并修正拼写、语法、逻辑错误
- **关键词提取**：提取文本中的核心关键词或短语
- **结构化整理**：将文本按主题或逻辑关系整理为清晰结构

#### AI模型选择
- **DeepSeek**：高质量的中文处理能力
- **豆包(Doubao)**：字节跳动的AI模型服务
- **Claude**：Anthropic的先进AI模型
- **LM Studio**：本地部署的AI模型服务

#### 高级设置
- **每段最大Token数**：控制单次处理的文本长度（1000-8000）
- **保持上下文连贯性**：在处理长文本时保持段落间的关联

### 3. 开始处理

1. 输入或加载要处理的文本
2. 选择合适的处理类型和AI模型
3. 调整高级设置（可选）
4. 点击"开始处理"按钮
5. 观察处理进度和状态更新
6. 处理完成后查看结果

### 4. 结果管理

#### 查看结果
- 处理结果会显示在右侧的"处理结果"标签页中
- 支持实时查看处理进度和最终结果

#### 操作结果
- **复制结果**：将处理结果复制到剪贴板
- **保存结果**：将结果保存为文本文件
- **导出文档**：导出为格式化的Markdown文档

#### 历史记录
- 切换到"处理历史"标签页查看所有处理记录
- 点击历史记录可重新加载之前的处理结果
- 支持清空历史记录功能

## 技术架构

### 核心组件

1. **LongTextProcessor**：长文本处理核心类
   - 继承自BaseAgent，提供统一的AI模型接口
   - 实现智能分段算法和上下文保持机制
   - 支持多种处理类型和结果合并策略

2. **LongTextProcessingGUI**：图形用户界面
   - 基于PySide6框架的现代化界面设计
   - 支持文件拖拽、实时进度显示、结果管理
   - 提供丰富的配置选项和用户交互功能

3. **LongTextProcessingWorker**：异步处理线程
   - 避免界面冻结的异步处理机制
   - 实时进度更新和错误处理
   - 支持处理任务的取消和超时控制

### 分段处理算法

1. **Token估算**：基于字符数估算文本的Token数量
2. **智能分割**：在句子边界处分割，保持语义完整性
3. **上下文传递**：将前一段的处理结果作为下一段的上下文
4. **结果合并**：根据处理类型采用不同的合并策略

## 配置说明

### 模型配置

不同AI模型需要相应的配置文件和API密钥：

- **DeepSeek**：需要DeepSeek API密钥
- **豆包(Doubao)**：需要字节跳动API配置
- **Claude**：需要Anthropic API密钥
- **LM Studio**：需要本地LM Studio服务运行

### 性能优化

- **Token限制**：根据模型能力调整每段最大Token数
- **并发处理**：支持多段落的异步处理
- **内存管理**：自动清理临时数据，避免内存泄漏

## 常见问题

### Q: 处理很长的文本时速度较慢？
A: 这是正常现象。长文本需要分段处理，每段都要调用AI模型API。可以适当增加"每段最大Token数"来减少分段数量，但要确保不超过模型的上下文限制。

### Q: 处理结果不连贯？
A: 确保开启"保持上下文连贯性"选项。该功能会将前一段的处理结果作为下一段的上下文，保持整体连贯性。

### Q: 支持哪些文件格式？
A: 目前支持TXT、MD、DOCX、DOC、RTF、SRT、VTT等格式。对于Word文档，需要安装python-docx库。

### Q: 如何选择合适的AI模型？
A: 
- **中文文本**：推荐使用DeepSeek或豆包
- **英文文本**：推荐使用Claude
- **本地部署**：使用LM Studio
- **特定需求**：根据模型特点选择

### Q: 处理失败怎么办？
A: 
1. 检查网络连接和API配置
2. 确认AI模型服务是否正常
3. 查看控制台日志获取详细错误信息
4. 尝试减少每段Token数或更换模型
